# ADR-0003: Trust Zones and Unified Stack Diagram

**Status:** Accepted  
**Date:** 2026-03-03  
**Authors:** Iris (Staff SRE)

---

## Context

The 9TEVE-OS stack spans user interfaces, agent runtimes, workflow engines, secrets management, and external APIs. Without explicit trust boundaries, the blast radius of a compromise is hard to reason about.

## Decision

We formalise **five trust zones** with distinct security properties and network controls:

```
Zone A  ──  User + UI
Zone B  ──  Control Plane (highest-trust internal)
Zone C  ──  Execution (Agent Runners, Flow Engine) — sandboxed
Zone D  ──  Governance + Secrets (Vault, Policy PDP) — restricted
Zone E  ──  External Systems (GitHub, LLM APIs, SaaS) — untrusted
```

### Conceptual Stack Diagram

```
[User]
  │  (OIDC / session)
  ▼
[UI Layer: LobeHub / ClawKitchen]  ──(docs)──► [Docs surfaces]
  │
  │  (Run request, API key)
  ▼
════════════════ TRUST ZONE B ════════════════
[Control Plane API + Run Orchestrator]
  │           │              │
  │           │              └──► [Policy PDP/PEP] ──► [AI Policy Analyser]
  │           │
  │           └──► [Telemetry Spine] ──► (logs / metrics / traces store)
  │
  └──► dispatch
         ▼
════════════════ TRUST ZONE C ════════════════
[Agent Runners: SWE-AF / OpenHands]
   │           │
   │           └──► [Memory: Mem0]
   │
   └──► [Flow Engine: n8n / Prefect] ──► connectors
          │
          ▼
════════════════ TRUST ZONE D ════════════════
[Vault Broker]   [Compliance: Comp]   [Formal Models: TLA+ specs]
   │
   ▼
════════════════ TRUST ZONE E ════════════════
[GitHub repos]   [LLM APIs (Gemini CLI)]   [3rd-party SaaS]
```

### Cross-Zone Communication Rules

| From → To     | Protocol          | Auth                   | Notes |
|---------------|-------------------|------------------------|-------|
| A → B         | HTTPS             | OIDC / API key + MFA   | Rate-limited at gateway |
| B → C         | gRPC / HTTPS      | mTLS + signed JWT      | Agent tokens are short-lived |
| B → D         | HTTPS             | mTLS + service cert    | Policy PDP accessed read-only |
| C → D         | HTTPS (mediated)  | Via Control Plane only | Agents never talk to Vault directly |
| C → E         | HTTPS             | Allowlist per policy   | Default deny; opened by policy profile |
| D → E         | None              | —                      | Vault has no outbound internet |

### Operational Contracts (SRE)

- Every log line carries: `trace_id`, `run_id`, `tenant_id`.
- **SLO targets**: Control Plane API 99.9% monthly; dispatch latency p95 < 2 s; policy decision p95 < 200 ms.
- **Failure modes**: Policy PDP failure → default deny on side effects; Vault unavailable → "no-secrets" mode.

## Consequences

- **Positive**: Explicit blast-radius containment; easy to reason about lateral movement.
- **Negative**: Zone C sandboxing requires container / network infrastructure investment.
- **MVP shortcut**: Zones are logical (same host, separate processes) for local dev; physical separation required before production.
