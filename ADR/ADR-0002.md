# ADR-0002: Agent Identity Model

**Status:** Accepted  
**Date:** 2026-03-03  
**Authors:** Theo (Security Engineer)

---

## Context

Agents in 9TEVE-OS are ephemeral processes that need to interact with repositories, LLM APIs, secrets, and each other. Without a clear identity model, we cannot enforce least-privilege access or produce a meaningful audit trail.

## Decision

We adopt a **three-layer identity model**:

| Layer | Principal | Mechanism |
|-------|-----------|-----------|
| Human | User login | OIDC/SAML (enterprise); API key (MVP) |
| Service | Control Plane, runners | mTLS certificates |
| Agent | Ephemeral runtime | Short-lived signed JWT (≤ 15 min) |

### Agent Identity Token Claims

```json
{
  "sub":               "coder-agent-17",
  "tenant_id":         "org-9teve-o",
  "project_id":        "9teve-os",
  "run_id":            "run_a1b2c3d4e5f6a7b8",
  "role":              "coder",
  "capabilities":      ["read_repo", "write_repo", "open_pr"],
  "policy_profile_id": "default",
  "exp":               1741000000,
  "trace_id":          "4bf92f3577b34da6a3ce929d0e0e4736"
}
```

### Permission Model

- **RBAC**: Broad role rights scoped to the run sandbox (`coder` can write to the branch, not to `main`).
- **Capability grants**: Narrow, time-boxed permissions for a specific run (e.g., `use_secret:github_token` for 10 minutes).

### Secrets Boundary

Agents **never** receive raw Vault tokens. The Control Plane mediates all secret access:
1. Agent requests a credential via a `CredentialRef` in its action envelope.
2. Control Plane authenticates the agent token, evaluates policy, then fetches the scoped credential from Vault.
3. Vault returns a short-lived credential (e.g., GitHub PAT scoped to the target repo, expiry = 10 min).
4. Every secret access is logged: `{run_id, agent_id, purpose, policy_decision}`.

### Multi-Tenant Isolation

`tenant_id` is **mandatory** on every storage key, queue topic, and artefact path. Cross-tenant reads are forbidden without an explicit break-glass policy (logged and alerted).

## Consequences

- **Positive**: Least-privilege by default; ephemeral tokens limit blast radius; full audit trail.
- **Negative**: Token rotation adds latency; agents must refresh tokens mid-run.
- **MVP Stub**: JWT signing uses HMAC-SHA256 with an `ATA_SECRET_KEY` environment variable. Replace with PKI before production.

## Alternatives Considered

- **Static API keys per agent**: Rejected — no expiry, over-permissive, not tenant-scoped.
- **PASETO v4**: Preferred long-term but adds a dependency; HMAC JWT is sufficient for MVP.
